## 2026-06-22-EXP-001 - Candidate-Snapshot Calibration Research Plan

- Time: 2026-06-22 23:14 CST
- Objective: Define the next research program for converting the current PM5M/PM15M signal from an
  empirical trigger into a calibrated, fee-aware digital-claim pricing rule.
- Hypothesis: The current `raw_edge = p_raw - ask` is not a reliable tradable edge unless
  `p_raw` is calibrated. The correct research object is every decision-time candidate snapshot, not
  only filled live/backtest trades. If calibrated net edge is real, realized return should increase
  monotonically by net-edge bucket out of sample.
- Data:
  - Primary calibration data: local recorded/replayed candidate snapshots from quality-passed
    Polymarket and Binance intervals.
  - Execution-quality data: live audit logs, order intents, fills, POST latency, visible book at
    decision, and replay comparator outputs.
  - Exclude intervals with Polymarket book gaps, ambiguous reconnect snapshots, snapshot lookahead
    risk, Binance/reference staleness, missing market metadata, missing settlement, or unrecoverable
    live/local clock alignment.
  - Use the agreed live-like timing model unless explicitly running a sensitivity test: Polymarket
    server-visible book timing, Binance reference visible at exchange time plus about `200 ms`, and
    live/backtest submit latency modeled separately.
- Code/config: Planning only. Expected implementation should add a candidate snapshot export and
  analysis pipeline without changing live trading rules first.
- Commands: Not applicable.
- Parameters:
  - Universe: BTC, ETH, SOL; PM5M and PM15M strategy families.
  - Candidate rows must include at least: `coin`, `horizon`, `strategy_instance_id`, `market_id`,
    `window_start`, `side`, `ts_server_visible`, `tau`, `p_raw`, `market_bid`, `market_ask`,
    `market_mid`, executable average fill prices for target sizes, book depth, spread,
    raw signal features, momentum features, sigma features, gate-pass flags,
    current-rule `would_trade`, actual-live `order_sent`/`filled` where available, and
    `final_outcome`.
  - Fees: use crypto taker fee in effective ask for taker simulations.
  - Grouping: evaluate by `coin`, `horizon`, `side`, `tau` bucket, and market/window block.
- Outputs:
  - Planned dataset: `candidate_snapshots.parquet` plus a data-quality manifest describing included
    and excluded intervals.
  - Planned reports: raw probability calibration tables, market baseline tables, incremental signal
    tests, execution-toxicity diagnostics, and net-edge rule simulations.
- Metrics:
  - Calibration: bucketed realized win rate vs `p_raw`, reliability curve, Brier score, log loss.
  - Market baseline: out-of-sample Brier/log-loss improvement from adding signal terms to
    `logit(market_mid)`.
  - Trading economics: realized PnL/share, profit factor, PnL/cash, drawdown, daily by-symbol PnL,
    and monotonicity by calibrated net-edge bucket.
  - Execution: simulated executable average price vs actual fill, miss rate, adverse movement after
    fill over `1s/3s/5s/10s`, and live-vs-replay mismatch classes.
- Interpretation:
  - Research order is fixed:
    1. Build and validate the all-candidate snapshot dataset.
    2. Diagnose whether `p_raw` is a probability by bucket, separated by symbol/horizon/side.
    3. Fit the minimal calibration model `q_cal = sigmoid(a + b * logit(p_raw))` using
       walk-forward splits.
    4. Test whether the signal adds information beyond Polymarket price with a market baseline:
       `logit(P(win)) = a + b * logit(market_mid)`, then add signal terms.
    5. Convert calibrated probability into taker net edge:
       `net_edge = q_cal - avg_fill_price - fee - slippage_buffer`.
    6. Diagnose execution toxicity by measuring post-fill fair-value or mid-price drift.
    7. Only after steps 1-6, simulate new rules such as `net_edge > threshold`, symbol-specific
       thresholds/caps, and direction lock with mandatory repricing before every add.
  - Fixed absolute price caps such as `ask <= 0.70` are diagnostic variables only, not final trading
    rules. They can identify high-price overconfidence but can also remove genuinely cheap high-
    probability claims.
  - PM15M direction lock should only define the allowed side. Every add must recompute current
    calibrated edge from current book/reference state.
  - Filled-trade-only analysis is insufficient because fills are selected by book state, latency,
    risk gates, and toxic liquidity. Prediction research uses all candidate snapshots; execution
    research uses the live-filled subset.
- Next:
  - Implement the candidate snapshot exporter against the latest local recorder/replay data and the
    current five-strategy live logic.
  - Produce the first report on `p_raw` bucket calibration and market-price baseline before changing
    live trading rules.
  - Keep live 1 USDC sizing as data collection only until the candidate-snapshot analysis identifies
    a stable calibrated net-edge rule.

## 2026-06-22-EXP-002 - Candidate-Snapshot Plan Hardening

- Time: 2026-06-22 23:20 CST
- Amends: 2026-06-22-EXP-001
- Objective: Tighten the candidate-snapshot calibration plan so the first research output cannot
  accidentally reintroduce selection bias or confuse predictive accuracy with tradable economics.
- Hypothesis: The first calibration pass is only useful if it records all side-level, model-priceable
  snapshots, separates market-probability tests from executable-price tests, and validates economic
  monotonicity out of sample.
- Data: Planning only, based on the PM5M/PM15M research discussion and existing live/local replay
  audit requirements.
- Code/config: Documentation only.
- Commands: Not applicable.
- Parameters:
  - Snapshot coverage is widened to all quality-passed `market x second x side` rows where the model
    can price the outcome, the order book is readable, and settlement can be mapped.
  - `gate_passed`, `raw_edge_passed`, `locked_side`, `would_trade_under_current_rule`, and
    `actual_live_filled` are recorded as fields. They must not decide whether a row exists.
  - Prediction baseline may use `market_mid`; tradable edge must use executable average fill price
    for the target size, plus fee and slippage/adverse-selection buffer.
  - Walk-forward splits must be by time/date or contiguous blocks, not random rows.
  - Direction lock is represented as two separate concepts: `locked_side` and
    `current_priced_side_edge`. Locking the side must never reuse the original signal probability or
    edge for later adds.
  - Execution toxicity should be measured both on actual live fills and on hypothetical IOC fills
    from candidate snapshots.
- Outputs:
  - First minimum report should contain only the three decisive tables:
    1. `p_raw` calibration by `coin / horizon / side`.
    2. Market-price baseline vs raw-signal OOS Brier/log-loss.
    3. Realized PnL/share by calibrated `net_edge` bucket.
- Metrics:
  - Probability validity: bucket sample count, average `p_raw`, realized win rate, Brier score, and
    log loss.
  - Incremental information: out-of-sample improvement over `logit(market_mid)` baseline.
  - Economic validity: monotonic realized PnL/share by `net_edge` bucket.
- Interpretation:
  - The strategy is not ready for a new rule unless all three conditions hold: probability
    calibration works, the signal adds information beyond market price, and `net_edge` ranks
    realized PnL/share monotonically.
  - Absolute price caps such as `ask <= 0.70` remain diagnostic features, not production rules.
  - If these three minimum tables do not support the signal, further cap tuning is unlikely to be a
    robust research path.
- Next:
  - Start implementation/research from the all-side candidate snapshot exporter.
  - Produce the three minimum tables before expanding into execution-toxicity and live rule changes.
